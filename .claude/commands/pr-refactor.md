현재 브랜치의 변경사항을 분석하여 Refactor PR을 작성해줘.

먼저 아래 명령어로 변경사항을 확인해:
1. 분기점 확인: `git merge-base HEAD origin/develop` (또는 적절한 부모 브랜치)
2. `git log <분기점>..HEAD --oneline` (현재 브랜치 커밋 목록)
3. `git diff <분기점>..HEAD --stat` (현재 브랜치 변경된 파일)
4. 필요시 주요 변경 파일 내용 확인

아래 템플릿 형식을 **정확히** 따라서 작성해:

```markdown
## 🔨 Refactor

### 🎯 리팩토링 목적
- [ ] 코드 가독성 향상
- [ ] 성능 개선
- [ ] 코드 중복 제거
- [ ] 아키텍처 개선
- [ ] 테스트 용이성 개선
- [ ] 기타:

### 📝 주요 변경사항
<!-- 구체적으로 어떤 부분을 어떻게 변경했는지 -->

### 📈 개선 효과
<!-- 리팩토링으로 인한 개선 효과 -->

### 🔄 마이그레이션 가이드
<!-- 다른 개발자들이 알아야 할 변경사항. 없으면 "없음" -->

### 🐵 Etc.
<!-- 기타 공유할 내용. 없으면 비워둬 -->
```

작성 규칙:
1. 리팩토링 목적은 해당하는 항목에 `[x]` 체크 (복수 선택 가능)
2. 주요 변경사항은 파일별 또는 기능별로 구분해서 설명
3. 개선 효과는 Before/After 비교 또는 구체적으로 표현
4. 한국어로 작성
5. 마크다운 코드블록 없이 바로 출력
6. 작성 완료 후 `.claude/pr-text.md` 파일에 저장
